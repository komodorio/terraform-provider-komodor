# komodor_policy_role_attachment (Resource)

Creates a logical binding between a Komodor Role and a Komodor Policy

## Example Usage

```terraform
resource "komodor_policy_v2" "my-policy" {
  name = "my-policy"

  statements {
    actions = ["get:daemonset", "edit:cronjob", "delete:service", "edit:job"]

    resources_scope {
      clusters   = ["kind-kind"]
      namespaces = ["default", "komodor"]
    }
  }
}

resource "komodor_role" "my-role" {
  name = "my-role"
}

resource "komodor_policy_role_attachment" "my-attachement" {
  role     = komodor_role.my-role.id
  policies = [komodor_policy_v2.my-policy.id]
}
```

This resource is non-authoritative: it manages only the policies listed in the current resource for a given role. Multiple `komodor_policy_role_attachment` resources may target the same role as long as they manage different policy subsets. Overlapping policies across resources are not a supported pattern.
